فایلی را پیدا کنید که پاسخ در آن است

zjm-rag یعنی RAG روی فایل‌های خودتان. zg پوشه‌هایتان را می‌گردد، Jev نتیجه‌ها را می‌خواند و می‌سنجد کدام فایل‌ها واقعاً پاسخ را در خود دارند، و بعد یک LLM فقط از روی همان فایل‌ها جواب می‌دهد و مسیرشان را هم می‌آورد.

فعلاً در مرحلهٔ اثبات مفهوم است: یک اسکریپت پایتون به نام rag.py. کتابخانه، خط فرمان، API روی HTTP و سرور MCP مشخصاتشان نوشته شده و قدم بعدی ساختن آن‌هاست.

کد منبع در GitHub نسخهٔ اثبات مفهوم را امتحان کنید

سه مرحله، هر کدام باریک‌تر از قبلی

جست‌وجو تور را پهن می‌اندازد و یک داور صید را سوا می‌کند. فقط فایل‌هایی که از این داوری رد شوند به مدل می‌رسند، پس مدل چند فایل کامل را می‌خواند، نه انبوهی از تکه‌های پراکنده.

۲۰ نتیجه، در حداکثر ۸ فایل

zg پیدا می‌کند

یک جست‌وجوی ترکیبی، هم کلیدواژه‌ای و هم معنایی، روی نمایهٔ محلی zg. اسکریپت ۲۰ نتیجهٔ اول را برمی‌دارد، آن‌ها را بر اساس فایل گروه می‌کند و از هر فایل چند تکهٔ کوتاه نگه می‌دارد.

۸ فایل، هر کدام با یک احتمال

Jev داوری می‌کند

یک درخواست به Jev، یعنی OpenRouter Decisions API، از همهٔ فایل‌ها یک سؤال را می‌پرسد: آیا این فایل چیزی را که پاسخ لازم دارد در خود دارد؟ Jev فقط همان تکه‌ها را می‌خواند و برای هر فایل یک احتمال برمی‌گرداند. اسکریپت همه را چاپ می‌کند، از بالاترین احتمال به پایین.

۳ فایل، یک پاسخ

LLM جواب می‌دهد

اسکریپت سه فایل اول را با یک دستور به claude CLI می‌دهد: فقط از روی همین فایل‌ها جواب بده، مسیر فایل را بیاور، و اگر پاسخ در آن‌ها نیست همین را بگو.

چه چیزی از رایانهٔ شما بیرون می‌رود

جست‌وجو محلی است، اما داوری و پاسخ نه. فقط پوشه‌هایی را به آن بدهید که حاضرید محتوایشان را در گفت‌وگو با همین سرویس‌ها بچسبانید.

zgروی رایانهٔ خودتان اجرا می‌شود، روی نمایهٔ یک کپی از پوشه‌هایتان.
Jevسؤال و حداکثر دو تکه از هر یک از ۸ فایل به OpenRouter می‌رود.
claudeسؤال و ۲۰٬۰۰۰ نویسهٔ اول هر یک از ۳ فایل انتخاب‌شده به Anthropic می‌رود.

آنچه امروز هست و آنچه در برنامه است

امروز

  • rag.py هر سه مرحله را در یک اسکریپت انجام می‌دهد. با --no-answer بعد از رتبه‌بندی می‌ایستد.
  • از سه فایلی که بالاترین رتبه را دارند جواب می‌دهد. هنوز آستانه‌ای در کار نیست.
  • چند تست unittest پارسر خروجی zg را با یک فایل نمونه بررسی می‌کنند و هیچ‌وقت zg، Jev یا LLM را صدا نمی‌زنند.

در برنامه، برای هر مشخصه یک pull request

  • کتابخانهٔ zjm_rag با index، find و ask. یک آستانه (به‌طور پیش‌فرض ۰٫۵) فایل‌ها را به پذیرفته و ردشده تقسیم می‌کند و هیچ فایلی بی‌سروصدا کنار نمی‌رود. مشخصات کتابخانه
  • فرمان zjm با خروجی --json و بررسی zjm doctor. مشخصات خط فرمان
  • zjm serve، یک API از نوع JSON روی 127.0.0.1 برای برنامه‌هایی به هر زبانی. مشخصات HTTP
  • zjm mcp، یک سرور MCP برای عامل‌های هوش مصنوعی، و یک اسکریپت نصب یک‌خطی. مشخصات MCP و نصب

نسخهٔ اثبات مفهوم را امتحان کنید

  • پایتون ۳٫۱۰ یا جدیدتر. اسکریپت فقط از کتابخانهٔ استاندارد استفاده می‌کند.
  • zg روی PATH: npm install -g @zvec/zvec-grep
  • یک اسکریپت کمکی jev-decisions برای صدا زدن Jev. این اسکریپت در این مخزن نیست، پس RAG_JEV را به نسخهٔ خودتان اشاره دهید. مشخصات کتابخانه آن را با یک کلاینت داخلی جایگزین می‌کند.
  • claude CLI، برای مرحلهٔ پاسخ.

پوشه‌هایی را که می‌خواهید جست‌وجو شوند کپی کنید و از کپی نمایه بسازید

mkdir -p /tmp/zjm-rag/corpus && cp -r ~/projects/some-repo /tmp/zjm-rag/corpus/
cd /tmp/zjm-rag/corpus && ZVEC_GREP_HOME=/tmp/zjm-rag/zghome zg index . --mode direct --hidden

بعد، از داخل یک کلون مخزن بپرسید

git clone https://github.com/cocodedk/zjm-rag.git && cd zjm-rag
python3 rag.py "which linter checks CSS files"              # rank, then answer
python3 rag.py --no-answer "which linter checks CSS files"  # rank only
