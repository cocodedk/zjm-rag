# zvec-grep 0.3.0

Move the pinned zg from 0.2.2 to 0.3.0, its Rust rewrite. Everything below was measured in a
throwaway 0.3.0 container against `evals/corpus` on 2026-11-15, the image part under the
launcher's own `docker run` flags. Where spec 07 describes the image, this one wins.

## What 0.3.0 changed

- `index` and `query` are no longer subcommands; a bare word is search text.
  `zg index . --embedding M` exits 1 (`unknown option: --embedding`).
  `zg query … -- Q` exits 0 and searches for `query Q`, with only a warning on stderr.
- A hit header has lost `matchedBy=…`. Output of `--preview none`, verbatim:

  ```
  #1 office/kontor-oslo.md:1-5
  heading: Kontoret i Oslo
  heading_level: 1
  1	# Kontoret i Oslo

  #2 code/search.py:118-126
  symbol: [function] find
  118	def find(query, lockers, keys=None, *, limit=8, …
  ```

  There is no `query groups` / `hits:` preamble. A one-line hit is `#1 one.md:1`. No hits is
  the single line `No matches.`, exit 0.
- An index built by 0.2.2 is refused, by a query and by `--index` alike: exit 1, stderr
  `Error: This index is incompatible with the current version of zg.` followed by the corpus
  path. `--index --rebuild` repairs it.

Unchanged: `--embedding`, `--mode direct`, `--hidden`, `--rebuild`, `--preview none`, `--limit`,
`-t`, `--hybrid=…`, `--fuse`, `--` before the question; both baked models; the index under
`<corpus>/.zvec-grep`; the model cache layout; indexing and querying with no network.

## Changes

1. `zjm_rag/zg.py`
   - `index_argv`: `["zg", "--index", ".", "--embedding", M, "--mode", "direct", "--hidden"]`,
     plus `--rebuild` as today.
   - `query_argv` and `query_argv_translations`: drop the `"query"` element; nothing else moves.
   - `HIT_RE`: `^#(\d+) (.+?):(\d+)(?:-(\d+))?$`. The 0.2.2 form is no longer parsed.
   - `incompatible(stderr)`: true when stderr contains `incompatible with the current version of zg`.
2. Lockers indexed by 0.2.2
   - `lockers.run_index`: when zg fails and `zg.incompatible(err)`, run it once more with
     `rebuild=True`. A second failure raises `zg index failed: …` and leaves `indexed` false, as today.
     So the next `file_add`, `file_put` or `file_remove` migrates a locker, sealed or plain.
   - `gather._run_zg_query`: when zg fails and `zg.incompatible(err)`, raise
     `ZjmError("locker NAME was indexed by an older zg; re-run a file operation")`. `find` and `ask`
     stay read-only and never rebuild; the message carries no path and no zg command.
3. `Dockerfile`: the image keeps only what zg needs to run. The first `RUN` (Node, npm, curl,
   gnupg, the nodesource script, the `rm -rf $Z/…` strip) is replaced by:

   ```dockerfile
   # zg is a native binary. Node only fetches it, so Node stays in this stage, and the image
   # takes the binary plus the four libraries it links against (`ldd`), nothing else.
   FROM node:22-slim AS zg
   RUN npm install -g @zvec/zvec-grep@0.3.0 \
       && cd /usr/local/lib/node_modules/@zvec/zvec-grep \
       && mkdir -p /zg/bin /zg/lib \
       && cp bin/zg.exe /zg/bin/zg \
       && cp lib/libzvec_c_api.so lib/libllama.so.0 lib/libggml.so.0 lib/libggml-base.so.0 /zg/lib/ \
       && cp node_modules/@zvec/zvec-grep-*/LICENSE /zg/LICENSE

   FROM python:3.12-slim

   RUN apt-get update \
       && apt-get install -y --no-install-recommends git age \
       && rm -rf /var/lib/apt/lists/*

   COPY --from=zg /zg /opt/zg
   RUN ln -s /opt/zg/bin/zg /usr/local/bin/zg
   ```

   - Both seed steps become `zg --index . --embedding … --mode direct --hidden`, and the seed `RUN`
     ends with `&& chmod -R a+rX /opt/zjm/models`. 0.3.0 writes its completion marker and
     `tokenizer_config.json` mode 0600, so without it uid 10001 fails every index and query with
     `unable to read completion marker: Permission denied`.
   - Everything from `WORKDIR /src` down is otherwise unchanged.

   Why each thing stays or goes, all measured:
   - Node, npm, curl, gnupg: gone. The binary indexes and queries with none of them installed.
   - `libonnxruntime*` and the fourteen `libggml-cpu-*` (41 MB): gone. Both baked models index and
     query without them. The four copied libraries are exactly what `ldd` lists; a fifth one in
     a later zg fails the seed step at build time.
   - `ca-certificates`: already in `python:3.12-slim` (148 CA certificates load); not installed again.
   - `git` stays for `git check-ignore`, `age` for sealed lockers, both models because spec 07 bakes both.
   - `/src` stays: 1 MB, and removing it needs a third stage.
   - The layer that carries the tools goes from 587 MB to 210 MB (112 MB apt, 98 MB zg).
4. Tests
   - `tests/fixtures/zg-query.md` is replaced by `tests/fixtures/zg-query-0.3.0.md` (already in the
     tree: a real 0.3.0 capture, 40 hits, first `code/__init__.py:1-9`, second
     `code/search.py:118-126`, last `code/http.py:25-121`). `test_parse_keeps_every_hit_with_lines`
     asserts those, ranks 1..40, and the one-line form `#9 one.md:7`.
   - Every argv assertion and every canned zg output in `tests/` moves to the 0.3.0 form; fakes that
     branch on `argv[1] == "index"` / `"query"` branch on `"--index" in argv` instead.
   - New: `test_incompatible_index_is_rebuilt_on_write` (the second zg call carries `--rebuild`,
     the manifest ends `indexed` true; when the rebuild fails too, `ZjmError` and `indexed` false).
   - New: `test_find_on_incompatible_index_names_the_locker` (the error names the locker, holds
     no path, and zg is called once).

## Not in this spec

- `ZVEC_GREP_HOME` and each locker's `zghome` folder. 0.3.0 wrote nothing there in these runs, but
  dropping them changes the locker layout.
- zg on the host, and the `zg index` / `zg query` wording in other repos' instructions.
- `evals/corpus`, a frozen snapshot, and the older specs that quote 0.2.2 commands.

## Acceptance

Exactly **131 tests**, all offline with injected runners.

By hand, once, through the `zjm` launcher with egress off (uid 10001, read-only root, no
network): build the image; `zjm doctor` passes; on a locker made by the 0.2.2 image, `find`
gives the older-zg error, a `file_add` then succeeds, and `find` returns hits; a new
`--multilingual` locker indexes and is found.
